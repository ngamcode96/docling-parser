# docling-parser

Minimal PDF parsing with **word-level bounding boxes**, using nothing but
[docling](https://github.com/docling-project/docling). OCR is on by default.

```
src/docling_parser/parser.py         parse_pdf() -> word boxes per page
src/docling_parser/easyocr_words.py  word-level EasyOCR, registered with docling
src/docling_parser/rapidocr_words.py word-level RapidOCR, registered with docling
src/docling_parser/viz.py            draw_word_boxes() -> page image with one box per word
notebooks/word_bboxes.ipynb    demo: parse + display boxes for each word
data/sample.pdf                digital PDF (docling technical report)
data/scanned.pdf               image-only PDF, generated by the notebook, to exercise OCR
```

## Setup

```bash
uv sync
uv run jupyter lab notebooks/word_bboxes.ipynb
```

The first OCR run downloads models: EasyOCR's into `~/.EasyOCR` (~100 MB),
RapidOCR's PP-OCRv6 ONNX files into the `rapidocr` package directory (~20 MB).

Note that with `rapidocr` installed, docling's *auto* engine selection
(`auto_ocr_model.py`) prefers RapidOCR over EasyOCR, so `word_level_ocr=False`
now runs RapidOCR. `ocr_engine=` pins the choice explicitly.

## Usage

```python
from docling_parser import parse_pdf, draw_word_boxes

parsed = parse_pdf("data/sample.pdf", ocr=True, image_scale=2.0)

for word in parsed.words:
    print(word.page_no, word.text, word.left, word.top, word.right, word.bottom)

draw_word_boxes(parsed.pages[0]).show()   # page render + a box per word
parsed.document.export_to_markdown()      # the usual DoclingDocument, still available
```

### Coordinates

`WordBox` boxes are in **PDF points, top-left origin**, matching
`page.width` / `page.height`. To get pixels of the rendered page image use
`word.scaled(page.image_scale)`.

### Where the boxes come from

docling exposes `char_cells`, `word_cells` and `textline_cells` per page (needs
`generate_parsed_pages=True`, which `parse_pdf` sets).

- **Digital text** → `word_cells`, i.e. exact word boxes straight from the PDF
  (`estimated=False`).
- **OCR** → a word-level engine (default), which returns one *measured* box per
  word (`estimated=False`).
- **Fallback** (`word_level_ocr=False`, or any other OCR engine) → docling's OCR
  engines return *text lines*, so each line is cut into words proportionally to
  their character offsets (`estimated=True`). Word-accurate for evenly-spaced
  text, approximate on justified or heavily kerned lines.

### Word-level OCR engines

Neither engine gives word boxes out of the box in docling, for different
reasons, and both can:

| | how docling calls it | what's missing | this repo |
|---|---|---|---|
| **EasyOCR** | `reader.readtext(im)`, no kwargs (`easyocr_model.py:219`) | its detector *does* find words, but the default `width_ths=0.5` merges them into lines | `easyocr_words.py` forwards `width_ths=0.0` and the other grouping thresholds |
| **RapidOCR** | `reader(im, use_det=…, use_cls=…, use_rec=…)` (`rapid_ocr_model.py:518`) | DBNet detects lines by design — no grouping to switch off — but `return_word_box=True` splits them via the recognizer's CTC alignment | `rapidocr_words.py` sets that flag and flattens `word_results` back into `boxes`/`txts`/`scores` |

Both subclass the docling model and register in docling's OCR factory as
`easyocr_words` / `rapidocr_words`.

**`parsed_page.word_cells` and OCR.** docling assigns OCR results to
`parsed_page.textline_cells` only (`base_ocr_model.py:385`), and in
`OcrMode.FULL_PAGE` it clears `word_cells` outright — so with a stock engine that
field is `[]` on any scanned page, whatever you configure. Since the engines here
emit genuine word cells, they mirror them into `word_cells` as well
(`word_cells.py: PublishWordCellsMixin`), keeping native text-layer words ahead of
OCR ones. That means the field works whether you go through `parse_pdf` or drive
`DocumentConverter` yourself:

```python
pipeline_options.ocr_options = word_level_ocr_options("rapidocr")
...
result.pages[0].parsed_page.word_cells   # 307 word cells, not []
```

### Measured

`data/scanned.pdf`, against the 315 words of the digital original as ground
truth. "text matches" = OCR word equals the ground-truth word; "IoU" = median
box overlap with the ground-truth box for those matches.

| mode | boxes | measured | matched | median IoU | time |
|---|---|---|---|---|---|
| EasyOCR lines + split | 303 | 13 | 269 | 0.523 | 6.7 s |
| RapidOCR lines + split | 305 | 3 | 285 | 0.613 | 3.6 s |
| EasyOCR word-level | 309 | 289 | 256 | **0.744** | 8.3 s |
| **RapidOCR word-level** | 307 | **307** | **292** | 0.683 | **3.5 s** |

RapidOCR wins on speed and text accuracy; EasyOCR's boxes hug the glyphs tighter.
`add_margin` trades one for the other on EasyOCR — 0.0 → IoU 0.764 with 250
matches, 0.1 (EasyOCR's own default) → IoU 0.697 with 268; this repo defaults to
0.05. Numbers are one page of one document: re-run the benchmark in
`notebooks/scan_test.ipynb` on your own material before picking.

Both sources are merged: native word boxes win, OCR lines are only split where
they do not overlap native words (so a scanned figure inside a digital page is
covered too).

### Useful options

```python
parse_pdf(
    "file.pdf",
    ocr=True,                    # False -> text layer only, much faster
    ocr_engine="rapidocr",       # or "easyocr" (default)
    word_level_ocr=True,         # False -> docling's auto engine, line boxes split into words
    force_full_page_ocr=True,    # OCR everything, ignore a broken text layer
    ocr_options=WordLevelEasyOcrOptions(lang=["en"], add_margin=0.0),  # full control
    image_scale=2.0,             # page render scale (2.0 ≈ 144 DPI)
    page_range=(1, 5),           # 1-based, inclusive
    do_table_structure=False,    # skip the table model if you only want words
)
```
